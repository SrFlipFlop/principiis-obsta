Request 3 — Find, archive and hand over engagement work

The library is growing. Add case-insensitive literal search over titles, descriptions and note text, both across Library and inside one collection. Uploaded binary contents are not searched. Users want an actual downloadable handover archive of selected visible documents, with metadata and original bytes.

Also change Delete: people have been losing documents accidentally. From now on Delete archives a document rather than permanently destroying it. Archived documents disappear from ordinary Library/collection lists and search, but their owner (personal) or collection owner can browse an Archive view, download them, and Restore them. Archived documents cannot be edited or moved until restored, including by editors. Readers and editors cannot see archived collection documents, even by an old direct link. Membership changes still apply to archived documents; a removed owner of an uploaded document does not gain archive access. Keep IDs, metadata and bytes across archive/restore. There is no permanent-delete feature in this request. Previously completed deletions need not be recovered.

Add GET /api/search?q={text}[&collection_id={id}] -> array with the same summary fields as /api/documents, matching any of the text fields above by literal substring, ignoring case. Empty q lists currently visible active documents. Search is scoped by current access and the optional collection. A query containing punctuation is ordinary text. GET /api/documents?state=archived[&collection_id={id}] lists accessible archived documents; default state remains active. Details include state ('active'|'archived'). DELETE /api/documents/{id} now returns 204 after archiving; repeating it is 204 for an authorized owner. POST /api/documents/{id}/restore -> 200 restored document. Existing GET/download still work for an archived document's authorized owner; other callers get 403 or 404.

POST /api/exports {document_ids:[...]} -> 200 application/zip attachment. A selection contains 1–20 distinct active document IDs. Reject the entire selection with 4xx if any ID is unavailable, archived or unauthorized; do not silently export a partial selection. Archive contains manifest.json with a documents array of {id,title,description,filename,path}, and one entry per document at a unique relative path named in the manifest. Note bytes are UTF-8; uploaded bytes are exact. Paths must be usable when unpacked into a new folder, regardless of original filenames. The format of those relative paths is your choice. Repeated original filenames must both work.

Browser: Library and each collection have Search field and Find action, with visible results or an empty-results message. Archive opens the current location's archived documents; each has Restore. Provide a checkbox labelled Select {title} for each active result and Export selected to download the ZIP. Keep ordinary Download, note/upload forms, collection roles and moves working. Restore returns the document to its original location. This request changes the prior delete contract, not document ownership or collection roles. Preserve persisted data when restarting or upgrading.
