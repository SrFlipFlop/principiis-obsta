Request 1 — Fieldwork document library

We are a small consultancy. Consultants currently keep engagement notes and client handouts in local folders. Build a working document portal: people log in, keep a personal library, upload client handouts, write notes, correct their metadata and download the original files. This should feel like a usable small application, not an API demonstration.

Start from this empty project. Use Python 3.12, Flask 3.1.2 and SQLite, with server-rendered HTML and ordinary JavaScript where useful. Choose the structure, schema and visual design. No external services are needed. For this first package use Flask, its bundled dependencies and the Python standard library only; list Flask==3.1.2 in requirements.txt. This keeps dependency preparation reproducible; use the ordinary Flask session and Werkzeug facilities and sqlite3 as needed. Supply requirements.txt and app.py; `python app.py` must serve on 0.0.0.0:8123. Store durable data below PORTAL_DATA_DIR (default ./data). A fresh directory starts empty; restarting with the same directory retains users, documents and file bytes. GET /ready returns HTTP 200 when ready. Keep dependency preparation separate from startup.

People can register a unique email and password, log in and log out. Use normal browser cookie sessions; API clients use the same login/session flow. Registration does not log the user in. A person's library is personal: only its owner can see, edit, download or delete a document. Logging out returns to the login screen. Bad login credentials return 401, duplicate email returns 409. Passwords are at least eight characters. No email delivery or password recovery is needed yet.

After login show the library, including title, filename, description and a way to open each document. Include a form to Upload a file with a title and description, and a form to Create note with title, description and plain-text content. Every detail page shows its metadata and note text (or original file information), allows editing title/description and note content, has Download and Delete actions, and offers a route back to Library. Confirm successful saves and deletions visibly. Uploads accept nonempty files up to 2 MiB; preserve bytes and the original filename for downloading. Notes are UTF-8 text downloads named note.txt. Titles are nonempty and at most 200 characters. Descriptions and notes are plain text, not rich HTML. File parsing, PDF conversion and inline file execution are not needed.

Minimal integration contract (additional routes/fields are fine):
- JSON request/response for the /api routes except multipart upload and raw download. GET /api/session returns {user:{id,email}} for a logged-in user, otherwise 401. POST /api/users {email,password} -> 201 {id,email}. POST /api/session {email,password} -> 200 {user:{id,email}} and session cookie. DELETE /api/session -> 204 and ends the session. Login/user responses never include a password.
- GET /api/documents -> 200 array of the current user's documents. Each summary has string id, title, description, filename and kind ('note' or 'file').
- POST /api/documents {title,description,content} creates a note -> 201 document. POST /api/uploads accepts multipart title, description and file -> 201 document.
- GET /api/documents/{id} -> 200 document (notes include content). PATCH same route accepts title, description and, for notes, content -> 200 updated document. DELETE same route -> 204; it no longer exists. Unknown/inaccessible documents return 403 or 404. Missing login returns 401 for document API routes. Invalid inputs return a 4xx JSON error without completing the requested mutation.
- GET /api/documents/{id}/download -> 200 original bytes as an attachment; filename is retained. Do not require callers to know storage paths.

Browser contract: use visible associated form labels and ordinary links/buttons so a keyboard user can use the whole flow. On the login page label fields Email and Password and provide Log in and Register actions; registration can have its own screen with the same fields and Create account. In the library provide links/buttons named Upload and Create note. On the respective forms label Title, Description, File or Content, and submit with Upload file or Save note. Each document has a link named exactly its title. Detail editing uses Title, Description and Content for notes, with Save changes, Download and Delete actions. Log out and Library are available when logged in. Layout, colors, icons, navigation internals and URLs for HTML pages are your choice. Opening / shows login or the logged-in library.
