Request 5 — Read-only client handout links

Give a client a handout without creating an account. A personal-document owner or collection owner can create a Client link for one active document. Editors/readers cannot. On document detail show Expiry seconds (integer 1–86400), Create client link, a copyable URL, and Revoke link for each current link. Anonymous clients opening that URL see title, description and a Download link; note content is displayed as plain text. They cannot edit or discover another document. Use a fresh unguessable token with at least 128 bits of randomness for each link.

POST /api/documents/{id}/shares {expires_in_seconds} -> 201 {id,url,expires_at}, where expires_at is a UTC RFC3339 timestamp and url is an absolute same-origin URL. GET /api/documents/{id}/shares -> [{id,url,expires_at,revoked}] for the current document owner. DELETE /api/shares/{id} -> 204 revokes it (repeat by an authorized owner is 204). GET /share/{token} serves the anonymous page and GET /share/{token}/download serves exact current bytes as attachment. A valid share is the sole anonymous exception to prior document-access rules; no /api document route becomes public. Unknown, revoked or expired tokens return 403, 404 or 410 without document metadata/bytes. Expiry uses server time. Creation time and expiry survive restart.

Archive or any location move permanently revokes that document's existing links, even after restore or moving it back. Collection membership changes do not revoke owner-created links unless ownership changes; a removed editor never controlled them. A link reflects subsequent edits of the active document. Owner-only link management follows the document's current location. Tokens are not included in ordinary document/list/search/export responses. Other behavior stays as before.
