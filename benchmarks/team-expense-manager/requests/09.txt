Request 9 — Longer lists and a receipt pack

Large teams need optional pagination on GET /api/expenses. With page_size (integer 1–100) and optional cursor, return {items,next_cursor}; without page_size keep the earlier array. Continue in ascending string-ID order after the previous page, using the same q, status, dates, category, team_id and page size. Invalid cursors or changed parameters return 4xx. With unchanged data each match appears once. Data changes between pages may change later matches; no snapshot guarantee is needed. Add a Next page action to browser results. Reports/CSV continue to cover all matches, not one page.

For bookkeeping, owners/reviewers can select 1–50 team expenses and download their receipts together. POST /api/teams/{id}/receipt-pack {expense_ids:[...]} returns an application/zip attachment containing manifest.json with expenses:[{id,merchant,amount_cents,filename,path}]. Each selected expense must belong to that team and have a receipt; an invalid selection returns 4xx as a whole. Duplicate IDs are invalid. Preserve exact receipt bytes and include both receipts when filenames repeat, each with its own manifest path. Order manifest entries by string expense ID. Add selection/download in the browser team list. Individual receipt download behavior remains.
