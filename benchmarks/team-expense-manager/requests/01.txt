Request 1 — Tally personal expense ledger

Build a small expense app for consultants who currently keep receipts in folders and copy amounts into spreadsheets. People register with email, name and password, sign in, keep their own expense ledger, and log out. Each expense has a string ID, merchant, description, spent_on date (YYYY-MM-DD), amount_cents (positive integer, at most 100000000), currency ('EUR'), created_at and updated_at. Merchant is nonempty, at most 200 characters; description is plain text. Amounts are integer EUR cents throughout the API; show two decimal places in browser forms and totals. Accept browser amounts with at most two fractional digits, such as 12.30; reject greater precision instead of rounding. No currency conversion or payments.

People can create, list, inspect, edit and delete their own expenses and optionally upload one receipt per expense. Receipt files are nonempty and at most 3 MiB. Preserve original filename and exact bytes; show the filename and a download action. A new receipt replaces the earlier one; DELETE receipt removes it. Build complete server-rendered browser workflows with navigation and visible save/delete confirmation. Layout and styling are yours.

Start from an empty project. Use C#/.NET 8, ASP.NET Core 8 and SQLite, with server-rendered pages and optional JavaScript. Compatible NuGet dependencies are allowed. Supply Tally.csproj at the project root. `dotnet restore Tally.csproj` then `dotnet run --project Tally.csproj --no-launch-profile --urls http://0.0.0.0:8123` starts the app. GET /ready returns 200 when ready. EXPENSE_DATA_DIR (default ./data) contains durable state; fresh storage starts empty and restart retains accounts, expense data and receipt bytes. No external service is needed.

API (additional fields/routes are fine):
- POST /api/users {email,name,password} -> 201 {id,email,name}; duplicate email -> 409. POST /api/session {email,password} -> 200 {user:{id,email,name}} and cookie; incorrect credentials -> 401. GET /api/session returns that user shape or 401. DELETE /api/session -> 204.
- GET /api/expenses -> array of expense summaries in string-ID ascending order. POST /api/expenses {merchant,description,spent_on,amount_cents,currency:'EUR'} -> 201 expense. GET /api/expenses/{id} -> expense; PATCH with one or more editable fields -> updated expense; DELETE -> 204.
- Summary/detail fields include the expense fields above, creator {id,email,name} and receipt ({id,filename,size} or null). PUT /api/expenses/{id}/receipt accepts multipart file and returns receipt metadata; GET .../receipt/download returns its bytes as attachment; DELETE .../receipt -> 204.
- Invalid product input returns 4xx JSON; unauthenticated API requests return 401. Browser and API use cookie login. All IDs are strings and timestamps UTC RFC3339.
