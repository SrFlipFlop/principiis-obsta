Request 3 — Handover and recovering deleted work

We need two things for engagement handovers: find old notes and download a selection of documents together. Add case-insensitive literal substring search over titles, descriptions and note text, in the caller's personal library by default or within the selected collection. Don't search uploaded binary contents. Search punctuation should behave like ordinary text.

Also, people keep deleting the wrong thing. Change Delete to archive instead of permanent removal. Archived items leave normal lists and search. The archive is an owner-only workspace: the personal-library owner or collection owner can browse it, download documents and restore them. While archived, a document is read-only. Restoring keeps its ID, location, metadata and bytes. There is no permanent-delete feature yet; already deleted items need not reappear.

For handovers, let people select 1–20 active documents and download a ZIP containing original files plus manifest.json. The manifest's documents array has {id,title,description,filename,path}, with path naming the corresponding ZIP entry. Include both documents when filenames repeat. If any selected item is unavailable, fail the selection rather than giving someone an incomplete handover. Notes use UTF-8 bytes. Keep existing roles, collaboration and personal-library behavior working. Preserve saved data during upgrade and restart.

Client changes: GET /api/search?q={text}[&collection_id={id}] returns document summaries. Empty q lists active documents. GET /api/documents?state=archived[&collection_id={id}] lists the archive; default is active. Details add state ('active'|'archived'). DELETE /api/documents/{id} returns 204 after archiving (including repeated archive requests). POST /api/documents/{id}/restore returns the restored document. POST /api/exports {document_ids:[...]} returns an application/zip attachment. Add search, selection/export and archive/restore to the browser workflow; use whatever layout fits the application.
