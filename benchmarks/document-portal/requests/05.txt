Request 5 — Read-only client handout links

We want to send a client a handout without asking them to register. A personal-library owner or collection owner can create and revoke links for active documents; readers/editors cannot manage them. The anonymous client page shows title, description, note text where applicable and a download action. It shows the latest content. Give owners a list of links, expiry times and revocation status.

Owners choose a lifetime in whole seconds from 1 to 86400. Links stop working at expiry or revocation. Archiving or moving a document cancels its existing links permanently. Membership changes alone leave owner-created links working. Links and expiry survive restart.

POST /api/documents/{id}/shares {expires_in_seconds} -> 201 {id,url,expires_at}, with an absolute portal URL and UTC RFC3339 expiry. GET the same endpoint -> [{id,url,expires_at,revoked}]. DELETE /api/shares/{id} -> 204, including repeat revocation by the owner. GET /share/{token} serves the client page; GET /share/{token}/download returns current bytes as attachment. Unavailable links return 403, 404 or 410. Add this workflow to document details; earlier workflows keep their behavior.
