Request 4 — Bring in a handout from a URL

Sometimes a client sends a download link instead of a file. Add Import URL beside Upload in Library and each collection. Let someone enter Source URL, Title and Description and choose Import handout. Show whether the import is pending, complete or failed, with a useful error and Retry import after failure. A completed import opens its ordinary file document. Keep existing documents, roles and all earlier behavior.

The URL must be an absolute http or https URL with no credentials or fragment. Fetch only publicly routable destinations: reject localhost, private, loopback, link-local, multicast, reserved and unspecified IPv4/IPv6 addresses, including a hostname that resolves to one. Recheck each redirect and resolved destination; do not send the portal user's cookies or credentials. Follow at most three redirects, allow at most five seconds per fetch and 2 MiB of response bytes (including a response without Content-Length); non-2xx, timeouts and oversized responses are failed imports. A successful fetch creates exactly one ordinary file document with exact response bytes. Use the last URL path component as filename after URL decoding, or handout.bin if absent; filenames remain download metadata, never storage paths. No response rendering or parsing is needed. The deployment may supply PORTAL_IMPORT_FIXTURE_ORIGIN, an absolute HTTP origin for a controlled handout service: only this exact configured scheme/host/port is an exception to the public-address rule. Do not allow arbitrary other internal destinations through that exception or redirects. Network policy applies equally to retries. Normal running needs no external service.

POST /api/imports {url,title,description,collection_id?} -> 202 {id,status:'pending'|'complete'|'failed',document_id,error}; GET /api/imports/{id} -> the same job shape, where document_id is a string only on completion and error is nonempty only on failure (otherwise null). Completion may be immediate. Polling must eventually show complete or failed after the bounded fetch. A job is private to its requesting user; import permission is the same as uploading into that location. Invalid fields or insufficient initial permission return 4xx without creating a job. A failed network job creates no document. POST /api/imports/{id}/retry -> 202 job, keeping its job ID; retry is allowed only for failed jobs and must recheck current location permission. Repeated polling never duplicates documents; retrying pending/complete jobs returns 4xx. Membership revocation before a retry prevents it. Job state survives process restart; interrupted pending work may become failed with a retryable error. No cross-user job listing is needed.
