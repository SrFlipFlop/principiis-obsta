Request 4 — Bring in a handout from a URL

Clients sometimes send a download link instead of a file. Add URL import into personal libraries and collections, using the same roles as uploading. Ask for URL, title and description. Fetch an http or https resource, supporting ordinary redirects. Only a final 2xx response completes an import; other statuses fail with an error. Completion creates one file document with the response bytes, using the final URL path filename or handout.bin if absent. Keep the existing 2 MiB file limit and finish or fail a fetch within five seconds.

Show pending, complete or failed status with a useful error and a retry action. Jobs belong to the requesting person. Retry keeps the job ID and uses their current ability to upload to that location. Failed jobs create no document; polling never duplicates documents. Jobs survive restart; interrupted work may become failed and retryable. Normal operation needs no service beyond the supplied URL. PORTAL_IMPORT_FIXTURE_ORIGIN may identify a controlled download service for integration clients.

POST /api/imports {url,title,description,collection_id?} -> 202 {id,status,document_id,error}; GET /api/imports/{id} returns the same shape. Completion may be immediate; document_id is a string only when complete, error is nonempty only when failed, otherwise null. POST /api/imports/{id}/retry -> 202 job; only failed jobs can be retried. Invalid initial product input returns 4xx without creating a job. Preserve earlier workflows and saved data.
