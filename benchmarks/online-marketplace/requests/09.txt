Request 9 — Help people browse and sellers reconcile orders

Add favorites for signed-in buyers. They can save/remove active listings and browse their current favorite listings. If a saved listing becomes draft, omit it from favorites until active again; saving is independent of cart contents. PUT /api/favorites/{listing_id} saves, DELETE removes (both 204, repeated operations allowed); GET /api/favorites returns an array of currently visible saved listings. Add the actions and a favorites page.

Catalog GET /api/listings now accepts q (case-insensitive literal substring in title/description source), seller_id and in_stock=true|false; combine supplied filters, defaulting to all active listings as before. in_stock=true means stock > 0; false means stock=0. Invalid values return 4xx. Add browser search/filter controls. Opt into pagination with page_size (1–100) and cursor: return {items,next_cursor}, ordered lexicographically by string ID. Continuation retains q, seller_id, in_stock and page_size, returning IDs after the previous page; changed parameters or invalid cursors return 4xx. With unchanged data every result appears once. Without page_size retain the array. No snapshot guarantee across data edits is needed.

Sellers also need GET /api/seller/orders/export?status={status}, an optional status filter over their own seller orders. Return UTF-8 CSV with order_id,checkout_id,status,buyer_name,subtotal_cents,discount_cents,total_cents,created_at, one row per order in string-ID order and ordinary CSV quoting. Omitted status includes all, including cancelled; invalid status returns 4xx. Add a browser export action. No other seller's orders or buyer emails belong in this report.
