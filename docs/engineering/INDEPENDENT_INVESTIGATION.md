# Independent evaluator-agent stage (#7)

Run `python3 -m principiis.investigation --snapshot RETAINED_SNAPSHOT --primary PRIMARY_JSON --config EVALUATOR_JSON --prompt PROMPT_FILE --prompt-version VERSION --output NEW_DIRECTORY`. This separately invoked stage never calls the writer or changes primary scoring. It accepts checkpoints from the ordinary controller or restricted evaluator; the primary file is referenced and hashed, never opened for writing. New oracle versions require explicit restricted evaluations into new directories and consistent rescoring; supplemental findings are not oracle revisions.

The trusted evaluator configuration has `version`, `model`, `settings`, `agent` (argv array), positive `timeout_seconds`, and `evidence` (object). Model/settings are explicit metadata for the selected evaluator executable; the operator must ensure they describe its effective configuration. No model or limits for a live pilot are selected here. The stage runs the supplied executable as a separate subprocess in a disposable checkpoint copy. Its stdin is JSON with `prompt`, `prompt_version`, and the copy's `checkpoint` path. stdout must be JSON with a `claims` array. Each claim has nonempty `id`, `root_cause`, and optional `evidence` lookup key. An ordinary noninteractive agent can implement this contract through an operator-owned wrapper; simulated executables exercise it without model calls.

Each evidence entry is an operator-owned object with `root_cause`, `scope` and `argv`. Evidence argv is never taken from the agent response. Only claims matching the entry's root cause run that executable, with the claim JSON on stdin and a fresh disposable snapshot as cwd. Proofs never inherit agent mutations or previous proof mutations. The executable must actually reproduce the declared property, return zero and emit `{"reproduced": true}` to verify it; `false` rejects it. Missing, mismatched, failing or malformed proof remains unresolved. Exit zero alone cannot verify a claim. The scope bounds what verification means; operator review of these executable proofs is necessary, just as for predefined oracles. The public tests use harmless seeded files, not benchmark vulnerabilities or hidden tests. Root-cause identity is operator adjudication, not semantic inference by this controller; repeated matching claims retain their evidence but contribute once to `verified_root_causes`.

This is a trusted orchestration boundary, **not a sandbox**. Agent and verifier executables run on the controller host, without inherited credentials/environment beyond a minimal PATH, and can access host paths. Use only reviewed operator executables here. They must dispatch untrusted application/browser probes to the restricted evaluator from #6; never execute generated application code directly on the host. Provision a separate evaluation runtime/account with development artifacts inaccessible for live use. Do not give agent executables access to primary storage or original checkpoints: disposable copies protect against ordinary writes only. Symlinks retain snapshot semantics and are not containment. No development context includes this config, prompt, agent response, tools, findings or evaluator notes.

`investigation.json` records the primary reference/hash, configuration/prompt hashes and versions, agent exit/error status, supplemental claims, root causes, evidence references and evaluation-only elapsed resource usage. Config/prompt are retained verbatim, so supply no secrets. Each executable retains argv, exit/error, duration, stdout/stderr files and their hashes. Evidence records link claims to these commands and outputs. Resources scope is `independent_evaluation`; hosted-model memory remains unknown rather than zero. Agent and proof commands reuse the measured subprocess helper: per-command timestamps, sampled local process-group RSS, retained exposed turn-completed token usage, timeout errors and process-group cleanup are available through `resources.measurement_refs`. Unknown token usage stays unknown. Only recognized exposed usage events count as token evidence; arbitrary response text supplies no billing inference. Failures retain partial logs and `evaluator_error`; successful empty investigation is distinct from failure. Existing directories are rejected. Inspect the artifact status: as with the controller, a recorded evaluator failure can exit zero.

Validation: `python3 -m unittest discover -s tests -p test_investigation_cli.py -v`. First red failed because the module was absent; green demonstrated a separate simulated executable, seeded executable evidence, duplicate root-cause handling, verified/rejected/unresolved statuses, evidence linkage, unchanged primary bytes/snapshot, explicit failure retention and output overwrite rejection. No live agent, paid execution or pilot ran.
