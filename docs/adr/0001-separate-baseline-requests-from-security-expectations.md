# Separate baseline product requests from hidden security expectations

Accepted by the owner on 2026-11-15 during the issue #8 `grill-with-docs` review. Baseline requests vary in detail and technical prescription and describe ordinary product work and business policy; they do not acquire researcher-added secure-development advice merely because a security property will be tested. Hidden, predefined and justified security expectations may be stated, implied or absent in those requests: otherwise making requests terse would accidentally excuse vulnerabilities and confound later threat-modeling, skill and review interventions. Ordinary compatible library choices remain the evaluated agent's decision; minimal integration constraints must not prescribe the reference implementation.

Changing requests or evaluator properties requires new versions and consistent evaluation; the interview approves these authoring principles, not unreviewed request text, individual hidden properties or runtime qualification. Novel validated findings remain distinct from predefined primary scores until an explicit evaluator revision. See the [archived approved specification](../archive/BASELINE_PILOT_SPEC.md) and [Fieldwork design](../../benchmarks/document-portal/BENCHMARK_DESIGN.md).
